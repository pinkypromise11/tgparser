# TelegramParser

Сбор вакансий из Telegram и публикация в настроенный целевой канал.

## Запуск

Требуется Node.js 20.18+ (проверено на Node.js 24), заполненный `.env`, конфигурация
`telegram-parser.config.json`, действующая Telegram-сессия и список каналов-источников.
Пути к сессии, источникам, фильтрам и состоянию задаются в конфигурации.

```powershell
npm install
npx playwright install chromium
node engine.js
```

Компьютер и процесс должны оставаться включёнными. После изменения кода
перезапустите процесс; не запускайте два экземпляра.

## Место назначения публикаций

Текущий канал — **VEU Jobs**, ID **`-1003963771418`**.
Единый параметр назначения — `targetChannel` в `telegram-parser.config.json`.
Из него читают назначение основной движок, оба обработчика подборок и вспомогательные
скрипты публикации и проверки постов. При запуске проверяется доступ к каналу и право
на публикацию. Обработчики требуют явно переданный канал назначения.

`telegram-parser.config.example.json` содержит настройки VEU Jobs для первой установки.
Скопируйте его в `telegram-parser.config.json` при настройке нового рабочего каталога.
Рабочий файл конфигурации и сессия исключены из Git. Для другой конфигурации передайте
`--config <файл>` или задайте `TELEGRAM_PARSER_CONFIG`.

Очереди VEU Jobs заданы отдельно:

- `digestStateDir`: `.telegram-parser/targets/3963771418/digests`;
- `linkedVacancyStateDir`: `.telegram-parser/targets/3963771418/linked-vacancies`.

При смене назначения укажите отдельные каталоги очередей для нового канала. Задания
с другим каналом назначения отклоняются перед публикацией.

## Вход без кода через Telegram Desktop

Если нужный аккаунт уже открыт в Telegram Desktop на этом компьютере, можно создать
отдельную сессию парсера без SMS и без телефона:

1. Остановите парсер. Переключите Telegram Desktop на нужный аккаунт.
2. Полностью закройте приложение через значок в трее → «Выйти из Telegram».
   Выходить из аккаунта не нужно.
3. Выполните `npm run login:desktop` из папки проекта.
4. Если появится запрос, введите локальный код-пароль Desktop и/или облачный пароль
   Telegram прямо в терминале.
5. После сообщения «Сессия сохранена» откройте Telegram Desktop и запустите `node engine.js`.

Номер выбранного аккаунта проверяется по `PHONE` в `.env`. Папка `tdata` читается
локально; исходная сессия используется только для подтверждения нового входа.
В файл `sessionFile` из конфигурации сохраняется отдельная новая сессия.
Для portable-версии укажите `npm run login:desktop -- --tdata "D:\путь\tdata"`.
Справка: `node scripts/login_desktop.js --help`.

## Подборки GrowGlobalJobs

`GrowGlobalJobs` (`-1004309301539`) обрабатывается отдельно: каждую минуту сохраняются
новые посты, затем последовательно читаются вакансии по ссылкам и создаётся подборка
для канала из `targetChannel` (сейчас VEU Jobs). Каждое прочитанное описание проходит тот же `isRelevant`
с `config/keywords.json`, затем тот же `analyzeVacancy`, что и обычные посты.
AI вызывается только после прохождения ключевых слов; `reject` исключается,
`certain` и `review` проходят дальше к саммари. Контекст остальных позиций не используется.
Текущие стоп-слова применяются буквально ко всему описанию: даже упоминание
`product`, `data` или `support` может исключить вакансию, как и в обычном потоке.

Первый запуск запоминает последний ID и начинает с новых постов. При следующих
запусках дочитывается пропущенное. Пост `/37` автоматически не публикуется.
Редактирование уже отправленных подборок не отслеживается.

Пункты сохраняют исходный порядок: название/компания, хештеги, русское саммари до
450 символов и исходный URL. Длинные подборки делятся на части до 3900 символов.
Отклонённые, закрытые и недоступные вакансии не публикуются; причины сохраняются
в `filters` локального JSON. Если подходящих позиций нет, сообщение не отправляется.
Оставшиеся позиции сохраняют номера из исходного поста, включая пропуски после фильтрации.
Условия только из Telegram и расхождения отмечаются отдельно.

HTML читается через Axios/Cheerio, JavaScript-страницы — через Chromium. Для Himalayas
используется [официальный публичный API](https://himalayas.app/api) с точным совпадением
URL и указанием источника. CAPTCHA/авторизация не обходятся. Публичные описания и
контекст соответствующей позиции передаются существующему LLM-клиенту; саммари
всё равно требуют человеческого внимания, особенно при `#проверить`.

## Постоянное чтение ссылок из остальных каналов

Движок также раз в минуту проверяет все подключённые, не исключённые каналы из
`config/channels_with_ids.json`. Одиночные вакансии и подборки с распознанными
внешними HTTP(S)-ссылками направляются в отдельную очередь **до** фильтрации текста
Telegram. Читается описание каждой позиции, затем применяются существующие жёсткий
и AI-фильтры. Публикуются только прошедшие позиции: хештеги, русское саммари, ссылка
и исходный номер. Исходный пост дополнительно обычным обработчиком не отправляется.
Посты без распознанных ссылок обрабатываются по прежним правилам.

При первом включении берутся только посты начиная с момента активации; последующие
запуски дочитывают пропущенное. GrowGlobalJobs сохраняет свою прежнюю очередь.
Состояние остальных источников и задания хранятся в каталоге `linkedVacancyStateDir`
из конфигурации.
Не удаляйте этот каталог: он защищает от повторной отправки и хранит незавершённые
задания. Ошибка одного источника или LLM-задания не останавливает остальные;
повторные попытки используют задержку, Telegram FloodWait учитывается.

Ссылки на соцсети, канал, главную страницу, рекламу и каталоги отбрасываются.
Распознавание ссылок эвристическое: неизвестные форматы могут быть пропущены.
Авторизация и CAPTCHA не обходятся; недоступные описания не публикуются.
Автоматический процесс не использует ручной веб-поиск из чата как резервный источник.
Работа продолжается только пока запущен `node engine.js`, включён компьютер и есть
доступ к Telegram, сайтам и LLM; автозапуск при входе в Windows не настраивается.

## Предпросмотр без публикации

```powershell
npm run digest:preview -- https://t.me/GrowGlobalJobs/37
```

Результат: `config/digest-preview/37.txt` и JSON с прочитанными страницами, анализом
и цитатами. Команда **никогда не отправляет сообщения**. Повторный запуск продолжает
незавершённый разбор. Дополнительные флаги:

- `--extract-only`: только прочитать Telegram и извлечь ссылки.
- `--fetch-only`: прочитать страницы без LLM-анализа.
- `--retry-unavailable`: повторить чтение ранее недоступных страниц.
- `--reanalyze`: заново проанализировать сохранённые страницы.
- `--reanalyze-item=5`: повторить анализ только пятой позиции предпросмотра.
- `--refetch`: заново прочитать и проанализировать все ссылки.
- `--refresh`: заново загрузить исходный Telegram-пост и сбросить его предпросмотр.

## Восстановление и проверки

Рабочие задания и курсор находятся в `digestStateDir` из конфигурации, отдельно от
предпросмотров и обычного `stateFile`. Не удаляйте этот каталог: он хранит очередь, готовые
части, их Telegram random ID и статусы отправки. При сбое API задание повторяется
на следующем цикле, завершённые позиции повторно не анализируются. Ошибки страниц
повторяются до трёх раз, затем сохраняются в отчёте об исключённых вакансиях. Уникальный ID отправки
сохраняется до обращения в Telegram и повторно используется после сетевого сбоя;
дедупликация также зависит от сохранности состояния и обработки ID сервером Telegram.
Проверка новых постов продолжается во время анализа предыдущей подборки.
Изменение правил инвалидирует отбор ещё не отправленных подборок, в том числе
старых предпросмотров без фильтра. Уже опубликованные сообщения не меняются.
Если правила сменились посреди отправки частей, задание останавливается для ручной
проверки, чтобы не смешивать разные варианты подборки.

`worker.lock` защищает от одновременной работы двух отправителей; блокировка умершего
процесса снимается автоматически. При запуске движка выводятся базовый ID,
обрабатываемая позиция, число отправленных частей и причины повторных попыток.

```powershell
npm test
$env:DIGEST_BROWSER_TEST='1'
node --test test/digest_browser.test.js
```

Обычные тесты работают без сети и API-ключей. Проверка Chromium отдельно запускает
браузер с локально подставленным HTML и не обращается к сайтам вакансий.
